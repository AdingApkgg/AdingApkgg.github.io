タブレットで KDE を動かす：できるが、まず代償を認めよう

作成日2026-11-17|更新日2026-11-17|ツールとシステムフラッシュ
|総文字数:738|読む時間:3分|閲覧数:|コメント数:

タブレットのブートローダーを解除し、root を取り、公式 306 に焼き戻したあと、次にやりたくなったのは「いじれる機械が一台増えた」ということだけでなく、ノート PC に近い仕事をさせることだった：LibreOffice、ターミナル、ブラウザ、お絵かき。

まず何なのかをはっきりさせておく：これは chroot であって、ネイティブ Linux ではない。 Android は下で動き続け、メモリを奪い、CPU を制限し、描画は直接出力ではなく X11 転送を通る。軽い事務作業ならなんとかなるが、4K 編集や大規模ビルドは期待しないほうがいい。

三つの道の取捨

  • ネイティブのデュアルブート（B スロットに Linux を入れる）：性能は最高だが、スロットを触る必要がある。解除したばかりで公式システムを焼いた直後に、スロット切り替えのリスクをもう一度単独で見積もるのは割に合わない。
  • Fedora + KDE：2026 年、sheng 上で実際にやっている人はいるが、状態は「実験」——リポジトリは GitHub Actions でその場でこねる rootfs.img で、作者は十時間前までまだ手を入れていた。導入は「次の ISO を焼く」という話ではない。
  • Termux + chroot：すべて /data の中で完結し、パーティションに触らず、失敗したらディレクトリを消してやり直せばいい。reboot すら要らないかもしれない。

三つ目を選んだ。Debian 13 のイメージには KDE Plasma が入っており、proot-distro は展開器として一度だけ使い、以後 proot を通らない。

成否を分ける三つの罠

この三点を知らない人は必ず踏むし、踏んだときの症状はどれも「性能が足りない」にそっくりだ。

一、Mesa は必ず差し替える。 Debian 標準の Mesa は DRM msm ドライバを使うが、Android カーネルは /dev/kgsl-3d0 しか公開していない。公式 Mesa をそのまま入れると llvmpipe のソフトウェアレンダリングになり、KWin はクリックにも反応しないほど固まる。lfdevs/mesa-for-android-container の kgsl ビルド（Adreno 740 対応、まさに chroot 用）に差し替え、インストール後に apt-mark hold を実行し、さらに glxinfo -B で renderer が FD740 / Adreno (TM) 740、OpenGL 4.x であることを確認する。llvmpipe しか残っていなければ失敗だ。

二、chroot で X を起動するには作法がある。 setenforce 0、TMPDIR は chroot の /tmp を指し、XKB_CONFIG_ROOT は chroot の xkb を指す。そして X サーバは termux-x11 コマンドではなく app_process で起動する。一つ欠ければ黒画面か xkbcomp のエラーになる。

三、Termux:X11 は sharedUid の APK を使う。 使わないと、Android は「X11 が前面、Termux が背面」という理由で Termux の CPU を絞り、デスクトップはあからさまにフレームを落とす。代償として、GitHub 署名の Termux しか受け付けず、F-Droid 版は署名が違うので同じ UID では入れられない。

root が与えるのは権限であって、スケジューリングの重みではない

これは最も誤解しやすい。

root があってもデスクトップが滑らかになるわけではない。速度制限と root は別の仕組みだ：

  • system_server は「このアプリが今見えているか」に応じて、プロセスツリー全体を top-app / foreground / background / cached の cgroup に押し込む。su で出てきたプロセスも Termux の子プロセスのままで、Termux のグループを継承し、su はそれを並べ直してはくれない。
  • 具体的な絞り方は cpuset.cpus（background/cached は小さいコアに押さえ込まれる）、cpu.weight（重みが一桁違う）、cgroup.freeze（cached に入って十秒でプロセスツリー全体が凍結される）。Termux が凍れば、その下にぶら下がる X サーバも一緒に凍り、デスクトップは止まる。

そこで 05-pin-priority.sh を一つ足した：cgroup.freeze を解凍し、cpu.weight を 1000 に上げ、cpuset.cpus で全コアを開放し、Termux と X サーバに oom_score_adj=-900、renice -10、taskset を付けてコアを固定する。

だがこれはパッチであって解薬ではない。 system_server は前面と背面を切り替えるたびにこれらのファイルを書き戻すので、一度離れて戻ればほぼ元通りになり、再実行が必要だ。これが効くのは CPU を取れるかどうかだけで、あなたが切り替えた瞬間に freezer がプロセスを凍らせるのは止められない。

最初からグループを落とさない本当の方法は sharedUid の APK で、代償は前述のとおりだ。

作業前の準備

  • Termux は GitHub Releases か F-Droid から入れる。Google Play 版は使わない（更新が止まっている）。Termux:X11 は nightly からダウンロードする。
  • 両方のアプリの省電力設定を「無制限」にする。
  • 15 GB 以上を空けておく（KDE のインストール後は約 4 GB）。
  • USB デバッグを有効にしておく。なにかあったら adb で救出する。
  • su できることが必要。

まとめ

desktop は立ち上がり、Chromium も LibreOffice も開け、ターミナルも使える。代償は、他のアプリに切り替えて戻ると一瞬固まること、バックグラウンドに長く置くと凍結されることだ。

これは「応急処置ができるタブレット」になったのであって、ノート PC ではない。その期待値を先に置いておけば、あとは許容できる操作コストでしかない。
