よく使うプロキシ設定まとめ

作成日2023-06-21|更新日2023-06-22|ツールとシステムシステムとネットワーク
|総文字数:2.5k|読む時間:11分|閲覧数:|コメント数:

はじめに

注意：以下の例はすべて架空のプロキシです。ご自身のプロキシに置き換えてください

プロキシを設定するのは、次のような場合のためです：

  • GFW防火長城を越える（略称翻墙）
  • 内网 から 外网 へアクセスする
  • 内网 から 内网镜像库 へアクセスする（npm、composer など）

プロキシの方式

プロキシの設定方法には、少なくとも次のようないくつかの方式があります：

  • 対象のプロキシマシンを設定する（よく使われる）

    例：http://yourProxyServer:port

  • pac による自動プロキシ設定を行う（ブラウザでよく使われる）

    例：http://example/a.pac

プロキシのアドレス

現在利用可能なプロキシが http://yourProxyServer:port であると仮定します。以降の例では、すべてこのプロキシを例として使います。

Windows CMD でのプロキシ設定

現在の CMD ウィンドウでのみ有効：

REM 设置代理
set http_proxy=http://yourProxyServer:port
set https_proxy=http://yourProxyServer:port

REM 查看代理
echo %http_proxy%
echo %https_proxy%

REM 取消代理(留空即可)
set http_proxy=
set https_proxy=

常に有効にしたい場合は、システム環境変数 http_proxy、https_proxy を設定し、Windows を再起動してください。

注意：

  • http_proxy と https_proxy はどちらも http://yourProxyServer:port に対応しますが、後者には https の s がない場合があります

Mac でのプロキシ設定

ここではコマンドラインでプロキシを設定する方法のみを説明します

~/.bash_profile または ~/.zshrc にプロキシ設定のショートカットを記述します：

# shadowsocks 翻墙用，不翻墙可不用
alias proxy_ss='export all_proxy=socks5://127.0.0.1:1086; export http_proxy=http://127.0.0.1:1087; export https_proxy=https://127.0.0.1:1087'

# 其他代理
alias proxy_dev='export http_proxy=http://yourProxyServer:port; export https_proxy=http://yourProxyServer:port'

# 取消所有代理设置
alias unproxy='unset all_proxy; unset http_proxy; unset https_proxy'

設定後は、設定ファイルを source するのを忘れないでください。

使用時は、shell で実行します（開発マシンを例に）：

# 设置代理
proxy_dev

# 取消代理
unproxy

単独のコマンド：

# 临时设置代理
export http_proxy=http://yourProxyServer:port
export https_proxy=http://yourProxyServer:port

# 查看代理
echo $http_proxy
echo $https_proxy

# 取消代理
unset http_proxy
unset https_proxy

Git のプロキシ設定

Git

# 全局：设置 Git 访问外网（如 github）的代理
git config --global http.proxy http://yourProxyServer:port

# 全局：查看 Git 代理
git config --global --get http.proxy

# 全局：删除 Git 代理
git config --global --unset http.proxy



# ----------- 下面是针对每个项目局部的，非全局 -----------------
# 设置 Git 访问外网（如 github）的代理
git config http.proxy http://yourProxyServer:port

# 查看 Git 代理
git config --get http.proxy

# 删除 Git 代理
git config --unset http.proxy

Git のユーザー名・メールアドレスの設定

# 设置 Git 全局：用户名、邮箱 ↓
git config --global user.name "youName"
git config --global user.email yourEmail@example.com

# 下面是针对每个 Git 项目的，非全局 ↓
git config user.email yourEmail@example.com
git config user.name "youName"

どちらをグローバルに設定し、どちらを現在のプロジェクトに設定するかは個人の必要性次第であり、絶対的なものはありません。

npm のプロキシ設定 + ミラー設定

npm

淘宝 npm ミラーを使用する（推奨）

この場合は、淘宝ミラー + あなたのプロキシ（ある場合）を同時に設定する必要があります

# ↓ 设置淘宝 npm 镜像
npm config set registry https://registry.npmmirror.com
# ↓ 若本来即可访问外网，无需下面代理设置
npm config set https-proxy http://yourProxyServer:port

npm 公式ミラーを使用する

プロキシを設定する（ある場合）：

npm config set proxy http://yourProxyServer:port
npm config set https-proxy http://yourProxyServer:port

npm のプロキシ・ミラーの確認方法

# 查看 npm 所有设置
npm config list

# 查看代理
npm config get proxy
npm config get https-proxy

# 查看镜像
npm config get registry

# 取消代理
npm config rm proxy
npm config rm https-proxy

yarn のプロキシ設定 + ミラー設定

yarn

# 设置 registry 镜像
yarn config set registry https://registry.npmmirror.com

# 设置代理（若有的话）
yarn config set proxy http://yourProxyServer:port

# 查看所有设置
yarn config list

# 查看镜像设置
yarn config get registry

# 查看某个设置
yarn config get proxy

yarn のグローバル設定： 用户目录/.yarnrc

注意：

  • プロキシを設定しても有効にならないことがありますが、原因は yarn.lock ファイルの問題である可能性があります。削除してやり直してみてください

    • 参考：yarnpkg/yarn#4890

nvm のプロキシ設定

nvm

# 设置代理（永久）
nvm proxy "http://yourProxyServer:port"

# 设置代理（临时，非必须）
set http_proxy=http://yourProxyServer:port
set https_proxy=http://yourProxyServer:port

# 查看代理
nvm proxy

# 删除代理
nvm proxy "none"

参考：https://github.com/coreybutler/nvm-windows#usage

Bower のプロキシ設定

Bower

.bowerrc ファイルを新規作成し、proxy と https-proxy を記述します：

{
  "directory": "bower_components",
  "proxy": "http://yourProxyServer:port/",
  "https-proxy": "http://yourProxyServer:port/"
}

3 つの設定方法をサポートします：

  • 現在のプロジェクト：当前目录（bower.json 的同级目录）
  • 現在のユーザーディレクトリ
  • システムのルートディレクトリ（Linux の / ディレクトリ）

参考：https://bower.io/docs/config/#placement--order

PHP Composer のプロキシ設定

Composer

Composer をインストールした後、Composer の使用時にはシステム（Win の CMD など）のプロキシが直接使用され、プロキシ設定ファイルはありません。

つまり、Windows では次のように CMD のプロキシを設定する必要があります

set http_proxy=yourProxyServer:port
set https_proxy=yourProxyServer:port

その後でなければ composer require packageName を実行できません

システムにこの 2 つの環境変数が設定されていれば、Composer のグローバルプロキシに相当します

PhpStorm、IntelliJ IDEA、PyCharm、WebStorm、Android Studio（または JetBrains 系のその他）のプロキシ設定

Jetbrains

File -> Settings -> Appearance & Behavior -> System Settings

-> HTTP Proxy -> Manual proxy configuration -> HTTP

-> Host name: yourProxyServer -> Port number: yourProxyPort

-> OK

Maven のプロキシ・ミラー設定

Maven

Maven のプロキシ・ミラー設定は内容が多いため、詳しくは 这里 を参照してください

Gradle のプロキシ設定

Gradle

  • 現在のプロジェクトに設定する場合：
    • 現在のプロジェクト内の gradle.properties を新規作成または編集します
  • グローバルに設定する場合：
    • 用户目录/.gradle/gradle.properties を新規作成または編集します

gradle.properties ファイルに以下の設定を追加します：

systemProp.http.proxyHost=yourProxyServer
systemProp.http.proxyPort=yourPort
systemProp.https.proxyHost=yourProxyServer
systemProp.https.proxyPort=yourPort

参考：https://docs.gradle.org/current/userguide/build_environment.html

Python の pip プロキシ設定

pip は Python のパッケージをインストールするために使用できます。

pip のプロキシ設定には 3 つの方法があります（いずれか 1 つを選択）：

  • システム環境変数

    • CMD のプロキシ設定と同様に、その後 pip install yourPackage を実行します。Windows の場合 ↓
    set http_proxy=http://yourProxyServer:port
set https_proxy=http://yourProxyServer:port

  • --proxy パラメータ

    • pip install yourPackage --proxy http://yourProxyServer:port

  • pip.ini 設定ファイル（推奨、永続的）

    • Windows を例にすると、ユーザーディレクトリにディレクトリとファイル %HOME%\pip\pip.ini を新規作成し、次の内容を記入します：

      [install]
proxy=http://yourProxyServer:port

    • 設定が成功したか確認：pip config list

pip のプロキシ設定に関する公式ドキュメント：https://pip.pypa.io/en/stable/user_guide/#using-a-proxy-server

VS Code のプロキシ設定

VSCode はデフォルトで http_proxy と https_proxy の環境変数からプロキシを取得します。

ただし手動で設定することもできます：File -> Preference -> Settings と進み、右側の User Settings に以下のコードを貼り付けます：

"http.proxy": "http://yourProxyServer:port",

Notepad++ のプロキシ設定

Notepad++

メニューバー -> 一番右のクエスチョンマーク ? -> 设置更新代理服务器 ->

  • Proxy server：yourProxyServer
  • Port：yourPort

Sublime のプロキシ設定

Sublime はデフォルトでシステムの PAC 設定を使用します。ブラウザでネットに接続できれば、Sublime も基本的にネット接続できます。

設定ファイルでプロキシをカスタマイズすることもできます：

  • 菜单栏 -> Preferences -> Settings -> 在左右任意一侧填入：
"http_proxy": "http://yourProxyServer:port",
"https_proxy": "http://yourProxyServer:port",

Eclipse のプロキシ設定

Eclipse のプロキシ設定方法：

  • Window -> Preferences -> General -> Network Connections -> 右側の Active Provider で Manual を選択 -> Proxy entries 表格 内の 1 行目の HTTP をダブルクリック -> Host に yourProxyServer を入力 -> Port に yourPort を入力 -> OK
  • HTTPS、SOCKS も同様に設定します

Atom エディタのプロキシ設定

Atom

次のコマンドを参照してください：

# 查看代理
apm config get https-proxy

# 查看所有配置（显示的结果的 `userconfig` 就是配置文件所在位置）
apm config get

参考：https://github.com/atom/apm#using-a-proxy

wget のプロキシ設定

wget Win

wget Linux

方法 01（一時的）：

  • まず Windows CMD のプロキシを設定します：

    set http_proxy=http://yourProxyServer:port
set https_proxy=http://yourProxyServer:port

  • または Linux シェルのプロキシ：

    export http_proxy=http://yourProxyServer:port
export https_proxy=http://yourProxyServer:port

  • その後、wget コマンドをそのまま使用できます

方法 02（永続的、推奨！）：

  • wget の設定ファイルを直接使用します。現在のユーザーのホームディレクトリにファイル .wgetrc（Linux では /etc/wgetrc）を新規作成します：

    http-proxy = yourProxyServer:port
https-proxy = yourProxyServer:port
ftp-proxy = yourProxyServer:port

  • その後、wget コマンドをそのまま使用できます

方法 03（一時的）：

  • wget コマンドに直接パラメータを追加します。例：
    • wget https://www.baidu.com -e https-proxy=yourProxyServer:port
    • または（いずれも https ではなく http）
    • wget http://www.baidu.com -e http-proxy=yourProxyServer:port

curl のプロキシ設定

curl

方法 01（一時的）：
（本記事は全 4 部構成のうちの第 2 部です。）

  • まず Windows CMD のプロキシを設定します：
    set http_proxy=yourProxyServer:port
set https_proxy=yourProxyServer:port
  • または Linux shell のプロキシ：
    export http_proxy=yourProxyServer:port
export https_proxy=yourProxyServer:port
  • その後は curl コマンドをそのまま使えます。例えば
    • curl http://www.baidu.com -o baidu.html

方法 02（永続的、推奨！）：

  • curl の設定ファイルを直接使います。現在のユーザーのホームディレクトリに設定ファイルを新規作成します（Win：_curlrc）（Linux：.curlrc）：
    proxy = yourProxyServer:port
  • その後は curl コマンドをそのまま使えます。例えば
    • curl http://www.baidu.com -o baidu.html

方法 03（一時的）：

  • curl コマンドに直接パラメータを追加します。例えば
    • curl https://www.baidu.com -o baidu.html -x yourProxyServer:port

      -x の小文字 x は proxy という意味です

Golang の go get プロキシ

Golang の go get はシステムの http_proxy を使用しますが、コードを取得する際には Git のプロキシを使用するので、
両方の手順を行う必要があります：

  1. システムプロキシ（つまり CMD プロキシ）を設定する
set http_proxy=yourProxyServer:port
  1. Git プロキシを設定する。前述の Git 代理设置 を参照
git config --global http.proxy http://yourProxyServer:port

参考：

  • https://stackoverflow.com/a/10385612/2752670
  • 公式参考：https://github.com/golang/go/wiki/GoGetProxyConfig

VSCode を使用する場合、VSCode に Go の依存ツールを自動ダウンロードさせたいなら、VSCode の settings.json にもプロキシを設定する必要があります：

"http.proxy": "http://yourProxyServer:port",

Navicat で外部ネットワークのデータベースに接続

Navicat は 通道地址 と 代理服务器 を同時に設定しなければならないようです。

注意：この方法はあまり安全ではありません。慎重に使用してください！

  • ステップ 01： Navicat のインストールディレクトリでファイルを見つけます： C:\Program Files\PremiumSoft\Navicat Premium\ntunnel_mysql.php （または対応する言語の php）。外部ネットワークの Web サービスディレクトリに配置します（ブラウザで http://IP:port/abc/ntunnel_mysql.php を開くとページが表示されます）
  • ステップ 02： 右键某个数据库连接 -> HTTP -> 使用 HTTP 通道 にチェック -> 通道地址 に http://IP:port/abc/ntunnel_mysql.php を入力 -> 下部の 代理服务器 -> 使用代理服务器 にチェック -> 主机 に yourPorxyServer を入力 -> 端口 に yourPort を入力 -> 测试连接 -> 确定

Virtual Box、VMware のプロキシ設定

一般ユーザーの仮想マシンは NAT モードを使うでしょう。

プロキシ設定：仮想マシン内のシステムも、外部の物理マシンと同じプロキシ設定をしないとネットに接続できません。

Xshell のプロキシ設定

あるセッションのプロパティ設定を開きます

  • Connection
  • Proxy
  • Browse
  • Add
    • Name：anyName（または任意の名前）
    • Type：HTTP 1.1
    • Host：yourProxyServer
    • Port：yourPort
    • OK
    • Close

SecureCRT のプロキシ設定

2 ステップで行います。まずグローバルにプロキシ項目を追加し、次に各接続で対応するプロキシ項目を選択します。

  1. グローバルにプロキシ項目を追加
  • Options
  • Global Options
  • Firewall
    • Add
      • Name：anyName（または任意の名前）
      • Type：HTTP (no authentication)
      • Hostname or IP：yourProxyServer
      • Port：yourPort
      • OK
  1. あなたの接続で、先ほど新規作成したプロキシ項目を選択
  • あなたの接続 -> プロパティ
  • Connection
  • SSH2
  • Firewall
  • 刚新建的代理项 を選択

Proxifier で他のソフトにプロキシを設定

Proxifier

前述の各ソフトがそれぞれプロキシを設定するのとは異なり、Proxifier は別の考え方です：他のソフトのために統一的にプロキシを設定します。

利点：

  • ソフトウェアごとに個別のプロキシ設定をする必要がない
  • プロキシ設定画面を持たないソフトウェアには Proxifier がとても適している
  • プロキシ対象ソフトウェアの実際の通信量を確認できる
  • Windows、Mac のどちらでも使用可能

欠点：

  • プロキシ設定が時に個別最適化しきれない（例：Git のグローバルプロキシと現在の Git プロジェクトのプロキシ）

手順：

  1. 菜单栏 Profile -> Proxy Servers -> Add -> Address に yourProxyServer を入力 -> Port に yourPort を入力 -> Protocol に HTTPS を入力 -> OK
  2. 菜单栏 Profile -> Proxification Rules -> Add -> Name は任意で入力 -> Applications で Browse ボタンからプロキシ対象にしたいソフトウェアの exe ファイルを選択 -> Action で前の手順で設定した yourProxyServer を選択 -> OK
