4つのルートのうち、マザーボードを賭けなくて済むのは1つだけ

作成日2026-11-17|更新日2026-11-17|ツールとシステムフラッシュ
|総文字数:1.2k|読む時間:5分|閲覧数:|コメント数:

結論から言う。最終的には 2026 年の中国製ツールを使い、一時的なカーネル root でエンジニアリング用の abl を 2 つのスロットに書き込み、fastboot に入ってアンロックを実行した。

この方法に至るまでに 3 つの案を試した。完成品のツール 2 つはその場で失敗し、ダウングレード案は途中まで進んで止まった。書き残すのは、各段階の「なぜダメか」が「どうやるか」より役に立つからだ。

出発点：309 と差し替えられたラッピング

手元の Xiaomi 13（fuxi）は HyperOS 3、バージョン番号 OS3.0.309.0.WMCCNXM、カーネル 5.15.194、セキュリティパッチ 2026-08-01 だ。

BL アンロックの通常ルートは「168 時間待ち + クイズ回答」で、遅いが確実だ。これを回避するにはコミュニティに 2 つの発想がある。申請時に偽装した端末情報で検証を騙すか、旧版の「設定」をシステムパーティションに戻して、申請窓口をラッピングのないバージョンに巻き戻すかだ。

完成品のツール 2 つは後者を採っている。HyperSploit と MlgmXyysd の Bypass だ。どちらも失敗したし、使い方が悪いわけでもない。どちらも 2023 年に旧ラッピング向けに書かれたもので、309 で RSA のラッピングが変わったためクライアントに対応する秘密鍵がなく、ツール自身が「patched」やパラメータ異常を吐く。彼らが示す唯一の回避策は「旧版 Settings へのロールバック」だ。

Settings のロールバックがぶつかった三重の壁

この道も 309 では途絶えた。しかも三つ同時に断たれた：

  1. 旧パッケージの versionCode は 34 で、システムに入っているのは 36。pm install -d、-r -d はすべて「ダウングレード」として弾かれる。
  2. バージョン番号を変えようとすれば APK に手を入れることになり、署名も変わる。しかも設定はシステムアプリで公式署名しか認めないため、書き換えて入れても are not updateable が出る。
  3. root を取って直接上書きする手はどうか。/system_ext は dm-verity で保護された読み取り専用パーティションだ。root シェルの cmd package は package サービスに繋がらず、「システム自身にインストールさせる」こともできない。

ここまでで端末はまだ純正状態のままで、正常に起動でき、文鎮化していない。無理押しより立ち止まることが大事だ。

書き込みゼロの案と、マザーボードを賭ける案

立ち止まってから資料を調べ直すと、まったく別の 2 つの道が見えた。

ひとつは selinux=permissive を起動パラメータにねじ込む方法。 具体的には fastboot oem set-gpu-preemption-value ... selinux=permissive、次に fastboot continue、そして一連の service call でメモリ上のシステムプロパティを書き換え、zygote を再起動する。

利点は強烈だ。どのパーティションにも書き込まない。パラメータはメモリ上にあり、再起動で消える。最悪の結果は getprop を叩いても 309 のままでプロパティが変わらないことで、リスクの上限は一度空振りするだけだ。欠点も明確で、作者が実機で試したのは HyperOS 2 であり、コメント欄にはすでに「2026 パッチに更新したらコマンドが効かない」という声がある。

もうひとつは 9008 の認可不要の深層書き込み。 この道を行く前に必ず読むべき判断基準がある。すべての機種で成り立つ話ではないからだ：

8Gen2 は 2026 年 2 月パッチ以下でしかツールによるアンロックができず、それより新しい版ではキオクシア製フラッシュでなく、かつ 9008 がヒューズ未切断の場合にのみ 9008 深層書き込みに進める。

こちらは 9 月のパッチなので、まずフラッシュを確認する：THGJFJT2T85BAT0C、キオクシア。

すると 9008 の結論はこうなる。行けるが、「保証期間内にいきなり賭けて、文鎮化したらサポートに送ってマザーボード交換」の類だ。ちょうど手に馴染んだ主力機にとって、これは気軽に試すものではなく、別途決断を要するコストだ。

順番はこうなった。まず書き込みゼロのものを試し、ダメなら賭けるかどうかを見る。

正解：abl を書く、ただし abl だけ

その後 JiGuang-8Gen2-tool に行き着いた。これは前の 2 つのツールとは種類が違う：

  • fuxi を明示的にサポートし；
  • キオクシアでも使えると明言し；
  • 手順は push が同梱する abl + preload で権限昇格 → fastboot で permissive 設定 → continue でシステムに戻る → root で dd により abl_a/abl_b を書き込み → アンロックイメージを流し込む、というもの。

書き込むのは abl パーティションであり、EDL 深層書き込みではない。abl はブートローダーそのもので、dd の 2 コマンドで戻せるから、文鎮化リスクは 9008 より一桁低い。しかもアンロックが完了すればシステム更新が公式 abl を書き戻すので、エンジニアリング abl の役目はそこで終わる——アンロック状態は別のパーティションに保存され、abl には依存しない。

コードは酷安の @御坂114515号 による二次改変版で、作者情報はスクリプトの冒頭に残されている。パッケージは GitHub から取得した 167 MB の 7z で、展開すると 1.4 GB、中には images/fuxi と images/sheng という 2 つの機種ディレクトリを含む完全なツールチェーンが入っている。

つまずいた 2 回はいずれも技術的な問題ではない

1 回目は「クリーンな Enforcing を要求」で止まった。以前に手動で権限昇格した際に SELinux を enforce=0 のままにしていたため、ツールは環境がクリーンでないと判断してそのまま終了した。

対処は簡単で、一度再起動するだけ。abl はまだ触っていないので再起動は安全だ。システムに戻ってから再実行すると、今度は enforce=1 で、そこでようやく先に進んだ。

二度目はドライバだ。ツールキットには adb.exe と fastboot.exe しか入っておらず、ドライバは含まれていないし、Win11 にも標準で入っていない。デバイスマネージャーに黄色い感嘆符が付いている状態では、adb devices は空だ。MiFlash（Xiaomi USB / QDLoader ドライバを同梱）を入れて初めて認識される。ここには直感に反する点がある：Zadig でデバイスを WinUSB に置き換えるな、fastboot が不安定になる。

手順のリズムについてもう一つ：スクリプトは push から abl の書き込みまで一続きのチェーンで、途中で手動再起動するとその状態で止まる。画面に「電源 + 音量下を押して fastboot に入れ」と要求してくるので、そのステップはそのまま従い、あとは何も触らない。

両スロットに書く

ツールは dd のステップで abl_a と abl_b の二つを書き込む。

片方のスロットだけ書いてもすぐには問題にならないが、もう片方は公式 abl のままで、アンロック後にスロットを切り替えると二つのスロットのブートが不一致になる。手で打つなら：

ls -l /data/local/tmp/abl.elf
dd if=/data/local/tmp/abl.elf of=/dev/block/by-name/abl_a bs=4096 conv=fsync
dd if=/data/local/tmp/abl.elf of=/dev/block/by-name/abl_b bs=4096 conv=fsync
sync

まず ls でファイルがあることを確認し（200 数 KB）、あれば dd。

仕上げ

アンロックに成功すると、flash.locked=0、unlocked: yes、オレンジ色の警告、起動時の 5 秒待ち。データは消去される。

振り返ると、この四つの道の順序は実は「書き壊しても救えるかどうか」で並べていた：ゼロ書き込み > abl 書き込み > EDL 深層書き込み。完成品ツールが使えなくなったからといって考え方が使えないわけではなく、それはまず今回どのパーティションを触るかを判断することが、まず動くツールを探すことより重要だと証明したにすぎない。

もう一つここに書いておくべきことがある：アンロック状態は永続的で、気軽にロックし直すな、ロックし直してから再度アンロックすると最初からやり直しになる。
